# City Temperature Management API

FastAPI-застосунок для керування містами та збору історії їхньої температури.

Складається з двох частин (аплікацій):

1. **City**: CRUD API для міст.
2. **Temperature**: отримує поточну температуру для всіх міст з OpenWeatherMap, зберігає її в базу та віддає історію.

## Запуск

### 1. Клонувати репозиторій і створити віртуальне середовище

```bash
git clone <repo-url>
cd py-fastapi-city-temperature-management-api

python -m venv venv
# Windows
venv\Scripts\activate
# Linux / macOS
source venv/bin/activate
```

### 2. Встановити залежності

```bash
pip install -r requirements.txt
```

### 3. Налаштувати змінні середовища

Створи файл `.env` у корені проєкту:

```
API_KEY=твій_ключ_openweathermap
```

Ключ можна безкоштовно отримати на [openweathermap.org](https://openweathermap.org/api).
Новий ключ може активуватися не одразу (до пари годин), до цього API повертає `401`.

### 4. Застосувати міграції

```bash
alembic upgrade head
```

Це створить файл бази `database.db` (SQLite) з таблицями `city` та `temperature`.

### 5. Запустити сервер

```bash
uvicorn main:app --reload
```

Документація (Swagger UI): http://127.0.0.1:8000/docs

## Ендпоінти

### Міста

| Метод | Шлях | Опис |
|---|---|---|
| POST | `/cities/` | створити місто |
| GET | `/cities/` | список міст |
| GET | `/cities/{city_id}` | одне місто |
| PUT | `/cities/{city_id}` | оновити місто |
| DELETE | `/cities/{city_id}` | видалити місто (разом з його температурами) |

### Температури

| Метод | Шлях | Опис |
|---|---|---|
| POST | `/temperatures/update` | отримати поточну температуру для всіх міст і зберегти її |
| GET | `/temperatures/` | вся історія температур |
| GET | `/temperatures/?city_id={city_id}` | історія температур конкретного міста |

### Приклад використання

1. Створити кілька міст: `POST /cities/` з тілом `{"name": "Kyiv", "additional_info": "Capital"}`.
2. Викликати `POST /temperatures/update`: для кожного міста додасться новий запис температури.
3. Подивитися історію: `GET /temperatures/` або `GET /temperatures/?city_id=1`.

## Проєктні рішення

- **Структура за аплікаціями.** `City` і `Temperature` мають власні `models`, `schemas`, `crud` та `router`. Це розділяє відповідальність і спрощує розширення.
- **Розділення шарів.** Функції в `crud` працюють лише з базою і повертають дані або `None`. HTTP-помилки (`404` тощо) кидаються в роутерах через `raise HTTPException`.
- **SQLAlchemy ORM + Alembic.** Схема бази керується міграціями, а не створюється вручну.
- **Pydantic-схеми.** Окремі схеми для створення, оновлення (усі поля необов'язкові) та читання (`from_attributes=True`). Оновлення використовує `model_dump(exclude_unset=True)`, тому змінюються лише передані поля.
- **Асинхронне отримання температури.** Запити до OpenWeatherMap виконуються через `httpx.AsyncClient` та `asyncio.gather`, тобто для всіх міст паралельно. Один спільний клієнт на весь виклик через `async with`.
- **Стійкість до помилок.** `asyncio.gather(..., return_exceptions=True)`: якщо для одного міста API не відповів (не знайдено, помилка мережі), це місто пропускається, а решта зберігається.
- **Історія, а не перезапис.** Кожен виклик `POST /temperatures/update` додає нові рядки в `temperature`, тому таблиця накопичує історію. Час запису (`date_time`) виставляє база через `server_default=func.now()`.
- **Каскадне видалення.** Видалення міста видаляє його температури (`cascade="all, delete-orphan"` на `DBCity.temperatures`). Видалення температури місто не зачіпає.
- **Секрети в `.env`.** API-ключ не зберігається в коді.

## Припущення та спрощення

- **База даних:** SQLite для простоти запуску. Для продакшену варто перейти на PostgreSQL (змінити `DATABASE_URL` і драйвер).
- **Синхронна сесія БД.** Асинхронною зроблено лише частину з HTTP-запитами до зовнішнього API. Звернення до бази синхронні (`Session`), для навчального проєкту з малою кількістю міст це прийнятно. Повний перехід на `AsyncSession` потребував би async-драйвера (`aiosqlite`/`asyncpg`).
- **Пошук температури за назвою міста** (параметр `q` в OpenWeatherMap). Цей вбудований геокодер у документації позначений як deprecated, але досі працює. Назви міст слід вводити англійською (наприклад, `Kyiv`, `Lviv`), за потреби з кодом країни (`Lutsk,UA`).
- **Температура в градусах Цельсія** (`units=metric`) і зберігається як `Float`.
- **Місто, яке API не знайшло, пропускається** без помилки; відповідь містить лише успішно збережені записи.
- **Без пагінації** у list-ендпоінтах: вони повертають усі записи.
- **Автентифікація та ліміти запитів** не реалізовані.
- Порожній список для `GET /temperatures/?city_id=...` означає «записів немає», а не помилку.
